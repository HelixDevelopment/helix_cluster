# Initial HelixCluster project research request

We MUST create a project with as much as possible full automation and fully automatic configuration setup wizards with very little to almost none interaction with user as possible! What we want to achieve / create? Todays computer hardware components prices have skyrocketed and assembling on workstation with AMD Threadreaper processor and 256 GB of ram has insane price(s)! Instead of this we want to create solution which will bind several relatively good computers / laptops into one single cluster-based system which will behave as a one consistent machine wrapping up all computer's resources into one block! All memory, CPU power, networking and everything we can bind should become one consistent block! From one main computer we shall start new session like tmux, then once such session is started it will run on consistent system block which behaves as one single powerful machine. All work done through such session will use available CPUs and memory of all joined computers. Computers can always join or leave the block. Some can be offline, and come back later. All this MUST BE fully dynamic! Computers will have the following family of processors and compatible hardware: Intel series (i7), AMD family (Ryzen 9), Apple Silicon (M3 Pro) ... We MUST support all major hardware - Apple, Intel, AMD. Same applies for graphic resources: Apple, Intel, AMD, Nvidia ... We must be able to easily join new computers! All communication will be done through the gigabit local network, however we MUST be able to join new systems into the block via SSH (and through the VPN). System MUST be aware about connectivity towards each block member and based on all this all behavior and tasks execution MUST BE fully dynamic and adaptable! Proper safety and backup mechanisms MUST BE in place, powerful caching mechanisms and powerful extra safe validation and invalidation! We MUST define cutting edge architecture which will be rock solid base for such solution! Some use cases that we MUST BE able to fulfill: executing Android AOSP codebase building using powerful computing block! Then, use of AI CLI agents which also need resources - Claude Code with dozens of parallel agents! Under the hood of system make sure we create proper layered technology stack that will make the whole thing literally fly! Do comprehensive investigation (web research) about all technical articles, research papers, opensource solutions and repositories available on GitHub and other platforms! Make sure we do deep analysis of all gathered materials, we do comprehensive planning and each decision we make we analyze even more from all angles! We MUST detect all possible sources of problems, blockers and showstopper and all scenarios with all possible bottlenecks! System MUST be fully ACID, stable, lighting fast with comprehensive mechanism(s) for error(s) detection, prevention and correction! Data safety and consistency MUST be guaranteed! Here are some technologies we could use, for everything else you should make decisions: C, C++, CUDA, Zig, Odin, BASH, Go lang + Gin Gonic, Apache Kafka, Apache Spark, RabbitMQ, Redis, Postgres and SQlite, and other relevant usable technolgoy. We MUST have whole architecture and development plan. All micro-services defined, all components! We MUST plan in advance how everything is going to work up to the smallest details! All solutions MUST be already planned with in depth architecture, development (up to class and line of code), diagrams and graphs, database schemes, and all possible in depth documentation which can be given to the development teams to incorporate this powerful game-changer first in the world solution! Instead of buying exoensive workstation at current bad times, we MUST BE able to gather fine pieces of hardware - PCs and Laptops and bind the together in consistent block. As the base for the sessions management we could build on top of this project which already wraps and implements tmux interface(s): https://github.com/vasic-digital/tmux (git@github.com:vasic-digital/tmux.git). We MUST extend it to support more flavors, so tmx is not the only one! We MUST have full control over everything! We MUST be able to track behavior, health and available resources of every block's child in real time! We MUST be able to predict failures and other problems in real time and be able to predict them even before it happens! We MUST create powerful learning 'brain' LLM driven which will be able to learn, self improve and self tune the configurations in real time and makes critical decisions when that is needed! All LLMs and other models System MUST obtain through the LLMsVerifier Submodule and features it provides: https://github.com/vasic-digital/LLMsVerifier (git@github.com:vasic-digital/LLMsVerifier.git). We are going to be able to provide powerful models for regular use like kimi, DeepSeek V4, Claude and others! System MUST be rock solid, without possibility to produce false positives, false negatives and to bluff! We MUST have full in-depth testing strategy and as a single source of truth for all tests execution and fully autonomous QA session we MUST incorporate fully Helix QA: https://github.com/HelixDevelopment/helixqa (git@github.com:HelixDevelopment/helixqa.git). Check all available Submodules in vasic-digital and HelixDevelopment organizations. We can incorporate any of it for particular use cases and contexts - many features are already fully developed. We fully control both organizations and all codebase under all of the repositories. We can extend, polish, fix or modify any of Submodules or solutions!
