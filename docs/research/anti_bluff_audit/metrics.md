# pkg/metrics — Anti-Bluff Audit

- **Test result:** PASS — 12 tests pass (`go test ./pkg/metrics/... -count=1 -v`), all in ~0.36s, 0 failures, 0 skips.

- **Risk:** MEDIUM

- **Real-behavior coverage:** This is a small, self-contained pure-Go package (Counter/Gauge/Histogram/Registry + Prometheus text exposition). The tests genuinely exercise the REAL implementation — there are no mocks or stubs substituting for production code. Several assertions are real sink-side checks:
  - `TestPrometheusHandler` drives the actual `PrometheusHandler()` through `httptest` and asserts on the serialized response body (`requests_total 42`, `active_connections 7`, the `le="0.1"` histogram bucket line, the `_count 2` line, and `# HELP` / `# TYPE` lines). This proves end-user-visible Prometheus output, not just that the handler ran.
  - `TestHistogram` checks exact bucket boundary counting (cumulative `le` semantics: 1/2/3), `sum` (25.5), and `count` (4) — real arithmetic behavior, including the over-bound observation (15) correctly excluded from finite buckets but counted in total.
  - Mutation-paired tests exist per Constitution 1.1: `TestCounter_ConcurrentInc_Mutation`, `TestGauge_ConcurrentMutation_Mutation`, `TestHistogram_ConcurrentObserve_Mutation` (concurrency/atomicity), `TestCounter_AddNegative_Mutation`, `TestCounter_ValueIsolation_Mutation` (per-instance state isolation), `TestRegistry_GetMissing` (negative path). These would fail if the corresponding behavior were removed.

- **PASS-bluff findings:**
  - **Concurrency mutation tests do not run under `-race`, so their atomicity claim is unproven.** `TestCounter_ConcurrentInc_Mutation` (package_test.go:149), `TestGauge_ConcurrentMutation_Mutation` (package_test.go:183), and `TestHistogram_ConcurrentObserve_Mutation` (package_test.go:206) only assert the final aggregate count/value. Because `atomic`/mutex operations and a naive non-synchronized implementation usually both yield the correct final total when goroutines are few and fast, these tests can PASS even if the atomics/locks were removed. The data race they claim to guard against is invisible without `-race`. As written they are weak (count-only) guards, not true mutation proofs of thread safety. The audit run did not use `-race`.
  - **No serialization test for the Histogram exposition body shape in isolation, and `+Inf`/`_sum` lines are unverified.** `TestPrometheusHandler` (package_test.go:96–133) checks one finite bucket line and `_count`, but never asserts the `_bucket{le="+Inf"}` line, the `_sum` line, or the `%g` float formatting that `serialize()` (package.go:204–210) emits. A regression that dropped `+Inf` or `_sum` (both required by Prometheus consumers) would still PASS. Partial sink-side verification.
  - **Registry ordering / multi-metric output not asserted.** `serialize()` sorts metric names (package.go:190); no test asserts deterministic ordering or that all three metric types co-exist correctly in one body. Behavior is only incidentally exercised.
  - **No failure / edge-path coverage for several real behaviors:** duplicate registration under the same name (silently overwrites the map entry, package.go:139/148/157 — untested, no test proves intended overwrite-vs-error semantics); `NewHistogram` with unsorted or empty buckets; `Observe` with NaN/Inf; `Get` type-assertion when a name is reused across types. Happy-path dominant.
  - **Minor tautology:** `TestDefaultBuckets` (package_test.go:135) asserts `len == 11` against a literal slice that the function returns verbatim — close to asserting a literal it just read, though the strictly-increasing check adds some value.
  - **No real-world wiring:** no in-module code imports `github.com/HelixDevelopment/helix_cluster/pkg/metrics` (verified by grep). The feature is library-grade and tests match that scope, so this is NOT a CLAUDE-1 end-user-usability violation here — but note no integration/e2e test exercises it as a deployed `/metrics` endpoint under a running server. The Herald submodule references are a different module path.

- **Recommended hardening:**
  1. Run/CI-gate the concurrency mutation tests with `-race` (e.g., a `go test -race ./pkg/metrics/...` job); without it, the atomicity claim is a PASS-bluff. Add an assertion comment documenting that these tests are only meaningful under `-race`.
  2. In `TestPrometheusHandler`, additionally assert the `request_duration_seconds_bucket{le="+Inf"} 2`, `request_duration_seconds_sum`, and exact `_count` lines, and assert the full ordered body (or a golden string) so dropped/`+Inf`/`_sum` lines fail the test.
  3. Add `TestRegistry_DuplicateName` to pin the intended overwrite-or-reject semantics, and `TestRegistry_Serialize_Ordering` to lock the sorted, multi-type output.
  4. Add histogram edge tests: empty buckets, unsorted buckets, `Observe(math.Inf(1))`/`Observe(math.NaN())`, and a boundary-equality case (`v == bucket`) to prove the `<=` cumulative semantics explicitly.
  5. Add a small integration test that mounts `PrometheusHandler()` on a real `httptest.Server`, issues an HTTP GET, and validates the parsed body — proving end-user `/metrics` scrape behavior, not just in-process handler invocation.
